Graph Pointers — Learn These Before Memorising Code

1. Classify graph first.
Directed or undirected? Weighted? Negative edges? Grid? Functional graph? DAG? This selects the algorithm.
2. Decide traversal state.
visited for components, parent for reconstruction, color for cycles/bipartite, dist for paths.
3. BFS rule.
Unweighted / equal-cost edges → BFS. First visit gives shortest edge-count distance.
4. DFS colors.
0=unseen, 1=active, 2=done. Gray-edge in directed graph = cycle. In undirected graph, ignore parent edge.
5. Weighted decision.
Non-negative → Dijkstra. Negative / cycle detection → Bellman–Ford. Small n + all pairs → Floyd–Warshall.
6. DAG superpower.
Topological order turns paths into linear DP: count = add, longest = max, shortest = min.
7. DSU use-case.
Static/dynamic connectivity and Kruskal MST. Union only changes answers when roots differ.
8. Directed structure.
SCC compresses cycles into a DAG. Functional graph = one cycle with inward trees per component.
9. Euler vs Hamiltonian.
Euler uses every edge once → degrees + Hierholzer. Hamiltonian uses every vertex once → bitmask/backtracking.
10. Flow mindset.
Capacity limits resource use. Residual reverse edges permit rerouting. Max-flow = min-cut for cut questions.

Traversal / Grid BFS / Components

Counting Rooms

grid DFS/BFS · connected components
1. Goal / Pattern
Count connected components in a 2D grid using 4-direction movement.
2. Best Approach
O(n·m) time, O(n·m) worst-case queue space. Iterative traversal avoids Java recursion overflow.
3. State / Invariant
Every cell is either wall, unvisited floor, or marked visited. One BFS/DFS marks exactly one room.
4. Algorithm
For each unvisited ., increment answer and flood-fill all reachable . cells.
5. Traversal Order
Any order works; each cell is marked when inserted, never when removed.
6. Catch / Hook
“Start a traversal only from unseen land.” Mark immediately to avoid inserting the same cell many times.
7. Similar / Difference
Number of Islands is identical. Labyrinth instead runs one BFS and reconstructs a shortest route.
8. Interview One-Liner
“Each unexplored floor cell begins one connected component, and flood fill consumes the entire room.”

import java.io.*;
import java.util.*;

public class Main {

    public static void main(String[] args) throws Exception {
        FastScanner fs = new FastScanner();
        int n = fs.nextInt(), m = fs.nextInt();
        char[][] grid = new char[n][];
        for (int i = 0; i < n; i++) grid[i] = fs.next().toCharArray();

        int[] q = new int[n * m];
        int[] dr = {1, -1, 0, 0};
        int[] dc = {0, 0, 1, -1};
        int rooms = 0;

        for (int sr = 0; sr < n; sr++) {
            for (int sc = 0; sc < m; sc++) {
                if (grid[sr][sc] != '.') continue;
                rooms++;
                int head = 0, tail = 0;
                q[tail++] = sr * m + sc;
                grid[sr][sc] = '#';

                while (head < tail) {
                    int id = q[head++];
                    int r = id / m, c = id % m;
                    for (int d = 0; d < 4; d++) {
                        int nr = r + dr[d], nc = c + dc[d];
                        if (nr < 0 || nr >= n || nc < 0 || nc >= m || grid[nr][nc] != '.') continue;
                        grid[nr][nc] = '#';
                        q[tail++] = nr * m + nc;
                    }
                }
            }
        }
        System.out.println(rooms);
    }

            return buffer[ptr++];

Labyrinth

grid BFS · shortest path reconstruction
1. Goal / Pattern
Find a shortest path in an unweighted grid and print the moves.
2. Best Approach
O(n·m) time, O(n·m) space. BFS is optimal because every move costs one.
3. State / Invariant
prev[r][c] stores the move used to first reach cell (r,c); first reach in BFS is shortest.
4. Algorithm
BFS from A. Save parent-direction for each first-seen cell. Backtrack from B using inverse moves.
5. Traversal Order
FIFO queue. Mark a cell at enqueue time so it gets only one parent.
6. Catch / Hook
“BFS parent is the shortest-path tree.” Store direction, not only visited.
7. Similar / Difference
Message Route is the same BFS on an adjacency list. Monsters adds a competing multi-source BFS clock.
8. Interview One-Liner
“BFS explores by path length, so the first parent recorded for B reconstructs a shortest route.”

Building Roads

components · connect graph
1. Goal / Pattern
Connect an undirected graph using the minimum number of added roads.
2. Best Approach
O(n+m) time, O(n+m) space with DFS/BFS components.
3. State / Invariant
One traversal from a representative visits exactly its connected component.
4. Algorithm
Collect one representative per component. Connect consecutive representatives.
5. Traversal Order
Any component order works. Number of roads is components − 1.
6. Catch / Hook
“k components need exactly k−1 bridges.” No DSU is needed because graph is static.
7. Similar / Difference
Road Construction dynamically maintains components with DSU after each new edge.
8. Interview One-Liner
“I find one node per component, then chain those representatives together.”

Message Route

BFS · unweighted shortest path
1. Goal / Pattern
Find a minimum-edge route from 1 to n in an unweighted undirected graph.
2. Best Approach
O(n+m) time, O(n) extra space. BFS.
3. State / Invariant
parent[v] is the predecessor that first discovers v; it lies on a shortest route from 1.
4. Algorithm
BFS from 1, stop after reachability is known, then follow parents n → 1.
5. Traversal Order
FIFO queue guarantees nondecreasing number of edges from source.
6. Catch / Hook
“First BFS visit is shortest; do not overwrite its parent.”
7. Similar / Difference
Labyrinth is the grid version. Dijkstra is required only when edge weights differ.
8. Interview One-Liner
“Because every edge costs one, BFS produces the shortest-path tree and parent links reconstruct the route.”

Building Teams

bipartite graph · 2-colouring
1. Goal / Pattern
Split an undirected graph into two groups so every edge crosses groups.
2. Best Approach
O(n+m) time, O(n) space with BFS/DFS two-colouring.
3. State / Invariant
color[v] ∈ {1,2}; every traversed edge must connect opposite colors.
4. Algorithm
Start every uncoloured component with color 1; assign neighbours 3-color[u].
5. Traversal Order
Run BFS from every uncoloured node because graph may be disconnected.
6. Catch / Hook
“Same-color edge means odd cycle means impossible.”
7. Similar / Difference
Round Trip searches for any cycle; this specifically detects odd cycles through parity conflict.
8. Interview One-Liner
“I alternate colors along edges; a conflict proves an odd cycle, so no valid two-team split exists.”

Round Trip

undirected cycle · DFS colors
1. Goal / Pattern
Find and print any cycle in an undirected graph.
2. Best Approach
O(n+m) time, O(n) extra space. Iterative DFS prevents stack overflow.
3. State / Invariant
state: 0=unseen, 1=in current DFS stack, 2=finished; parent rebuilds a found cycle.
4. Algorithm
During DFS, an edge to a gray node other than parent closes a cycle.
5. Traversal Order
Use explicit stack frames and per-node adjacency index to simulate recursive DFS.
6. Catch / Hook
“Undirected DFS: ignore only the edge back to parent.”
7. Similar / Difference
Round Trip II is directed: every edge to a gray node is a back edge; no parent-edge skip.
8. Interview One-Liner
“A non-parent edge to an ancestor closes a cycle, which I rebuild through parent pointers.”

Monsters

multi-source BFS · escape before hazard
1. Goal / Pattern
Escape a grid while hazards spread one cell per minute.
2. Best Approach
O(n·m) time, O(n·m) space. Two BFS passes: hazards first, player second.
3. State / Invariant
monsterTime[r][c] is earliest danger arrival; player may enter only at strictly smaller time.
4. Algorithm
Multi-source BFS from all M cells. BFS from A while enforcing nextTime < monsterTime.
5. Traversal Order
Hazard BFS must finish before player BFS. Player BFS still gives shortest valid escape.
6. Catch / Hook

Shortest Paths — Dijkstra, Bellman–Ford, Floyd

Shortest Routes I

Dijkstra · non-negative weights
1. Goal / Pattern
Single-source shortest distances in a directed graph with non-negative edge weights.
2. Best Approach
O((n+m) log n) time, O(n+m) space using Dijkstra + min-heap.
3. State / Invariant
dist[v] is best known source-to-v distance. A non-stale heap pop finalizes it.
4. Algorithm
Relax every outgoing edge from the cheapest currently unsettled node.
5. Traversal Order
Priority queue ordered by distance. Ignore stale entries instead of decrease-key.
6. Catch / Hook
“Dijkstra requires non-negative weights.” Use long for distance.

Investigation is Dijkstra plus path-count/min-edge/max-edge metadata. Bellman-Ford handles negative edges.

Shortest Routes II

Floyd–Warshall · all pairs
1. Goal / Pattern
Answer many shortest-path queries when n is small enough for all-pairs preprocessing.
2. Best Approach
O(n³ + q) time, O(n²) space. Floyd–Warshall for n≤500.
3. State / Invariant
After intermediate loop k, dist[i][j] uses only vertices 0..k internally.
4. Algorithm
For every k, try path i → k → j against current direct best.
5. Traversal Order
k must be outermost; it defines allowed intermediates.
6. Catch / Hook
“k outermost is the Floyd invariant.” Initialize diagonal to 0 and keep minimum parallel edge.
7. Similar / Difference
Shortest Routes I is one source with large n; this preprocesses every pair for many queries.
8. Interview One-Liner

High Score

Bellman–Ford · positive cycle relevance
1. Goal / Pattern
Maximize path score from 1 to n; output −1 only if an improving cycle can affect the destination.
2. Best Approach
O(n·m) time, O(n+m) space using maximizing Bellman–Ford plus reverse reachability.
3. State / Invariant
dist[v] is best score using at most current iteration number of edges.
4. Algorithm
Relax maximum scores n−1 times. A relaxable edge afterward signals a positive cycle; it matters only if its endpoint reaches n.
5. Traversal Order
Bellman–Ford repeatedly scans every directed edge; no priority queue because weights/cycles invalidate Dijkstra.
6. Catch / Hook
“A good cycle matters only when reachable from 1 and able to reach n.”
7. Similar / Difference
Cycle Finding detects any negative cycle anywhere. High Score filters cycles irrelevant to the 1→n answer.
8. Interview One-Liner
“I detect a score-improving cycle after n−1 relaxations and reject only when it can still flow into n.”

Flight Discount

two Dijkstras · one discounted edge
1. Goal / Pattern
Find shortest 1→n route when exactly one directed edge may cost half.
2. Best Approach
O((n+m) log n) time, O(n+m) space: Dijkstra from source and Dijkstra from target on reversed graph.
3. State / Invariant
from1[u] and toN[v] are independent shortest segments around the discounted edge u→v.
4. Algorithm
Try each edge as coupon edge: from1[u] + w/2 + toN[v].
5. Traversal Order
Run two standard Dijkstras first; only then scan original edges.
6. Catch / Hook
“Fix the special edge; shortest path splits into prefix + special + suffix.” Integer division is required.
7. Similar / Difference
Shortest Routes I has no special edge. This avoids a 2-layer Dijkstra by enumerating the coupon edge.
8. Interview One-Liner
“Once I choose the discounted edge, the best prefix and suffix are ordinary shortest paths.”

Cycle Finding

Bellman–Ford · negative cycle reconstruction
1. Goal / Pattern
Detect and print any negative cycle in a directed weighted graph.
2. Best Approach
O(n·m) time, O(n) space via Bellman–Ford with virtual source behavior.
3. State / Invariant
parent[v] is the edge predecessor used by last relaxation. Distances start at 0 so every component is considered.
4. Algorithm
Relax n times. If a vertex changes on iteration n, walk parent n times to enter the cycle, then walk parents until repeat.
5. Traversal Order
Every iteration scans every edge. This is required to propagate effects of paths of increasing edge count.
6. Catch / Hook
“Walk parents n times first: only then are you guaranteed inside the cycle.”
7. Similar / Difference
High Score uses the same relaxation principle but asks whether a positive cycle affects a particular source-destination path.
8. Interview One-Liner
“A relaxation on the nth pass proves a negative cycle; parent pointers recover one.”

Flight Routes

k shortest paths · repeated Dijkstra pops
1. Goal / Pattern
Find the k smallest route costs from 1 to n in a positive-weight directed graph.
2. Best Approach
O(k·m log(k·n)) time, O(k·n) effective states. Priority queue with at most k accepted pops per vertex.
3. State / Invariant
The t-th accepted heap pop for a node is its t-th shortest route distance.
4. Algorithm
Pop cheapest candidate; accept node only k times; expand accepted candidates. Record pops for n.
5. Traversal Order
Global min-heap order. Do not use a single visited boolean: each node needs up to k distances.
6. Catch / Hook
“Visited once is wrong; count accepted pops per node.”
7. Similar / Difference
Dijkstra keeps only first pop per vertex. Here each vertex can legitimately appear k times.
8. Interview One-Liner

Investigation

Dijkstra + shortest-path metadata
1. Goal / Pattern
Find shortest distance plus number of shortest routes and min/max number of edges among them.
2. Best Approach
O((n+m) log n) time, O(n+m) space: Dijkstra with parallel metadata.
3. State / Invariant
For each v: shortest dist, number ways, minimum flights minE, maximum flights maxE among shortest routes.
4. Algorithm
Strict improvement replaces all metadata; equal-distance relaxation adds ways and merges min/max edge counts.
5. Traversal Order
Positive weights ensure all equal-distance predecessors are popped before their longer-distance successor.
6. Catch / Hook
“Shorter replaces; equal merges.” Do not add an equal-distance state to heap unnecessarily.
7. Similar / Difference

Longest Flight Route

DAG DP · topological order
1. Goal / Pattern
Find a maximum-number-of-vertices route from 1 to n in a directed acyclic graph.
2. Best Approach
O(n+m) time, O(n+m) space: topological sort then longest-path DP.
3. State / Invariant
dp[v] is maximum route length ending at v from source 1; parent[v] rebuilds it.
4. Algorithm
Process vertices in topological order and relax with max(dp[v], dp[u]+1).
5. Traversal Order
Topological order is essential: all predecessors of u are finalized before u.
6. Catch / Hook
“Longest path is easy only after cycles are removed.” Initialize unreachable states to negative infinity.
7. Similar / Difference
Shortest path in weighted general graph uses Dijkstra/Bellman–Ford; a DAG permits simple max DP.
8. Interview One-Liner
“A topological order turns every edge into a forward DP transition, so longest path becomes linear.”

3. State / Invariant

Planets Queries II

functional graph · distance queries
1. Goal / Pattern
Find number of forward teleports from a to b, or prove b is unreachable.
2. Best Approach
O((n+q) log n) time, O(n log n) space: prune trees, label cycles, binary lift tree ancestors.
3. State / Invariant
Each component is one directed cycle with inward trees. Store component, depth-to-cycle, cycle entry, cycle position.
4. Algorithm
If b is tree, a must be in its ancestor chain. If b is cycle, move a to entry then rotate around cycle.
5. Traversal Order
Remove indegree-0 nodes; process removed nodes in reverse to propagate cycle metadata outward.
6. Catch / Hook
“Tree target: only descendants can reach it. Cycle target: everyone in component eventually reaches it.”
7. Similar / Difference
Planets Queries I only computes successor jumps; this first classifies cycle versus tree positions.
8. Interview One-Liner
“A functional component is a cycle with reverse trees, so queries split into ancestor checks or cycle rotation.”

1. Goal / Pattern
Connect all undirected vertices with minimum total road cost.
2. Best Approach
O(m log m) time, O(n+m) space: sort edges then Kruskal DSU.
3. State / Invariant

Planets and Kingdoms

SCC · iterative Kosaraju
1. Goal / Pattern
Partition a directed graph into strongly connected components.
2. Best Approach
O(n+m) time, O(n+m) space using two-pass Kosaraju.
3. State / Invariant
First-pass finish order puts SCC sources/sinks in useful reverse order; second pass on reversed graph cannot cross to unassigned SCCs.
4. Algorithm
Iterative DFS on original graph for finish order; reverse order DFS on reversed graph assigns component ids.
5. Traversal Order
Second pass must process vertices in reverse finishing order.
6. Catch / Hook
“Finish order on G, component flood fill on Gᵀ.” Avoid recursive DFS for n=2e5 in Java.
7. Similar / Difference
Flight Routes Check tests whether there is exactly one SCC. Giant Pizza and Coin Collector use SCC condensation afterward.
8. Interview One-Liner
“Kosaraju’s finish order ensures each reverse-graph traversal extracts exactly one SCC.”

            rg[v].add(u);
        }

        ArrayList<Integer> order = new ArrayList<>(n);
        int[] stack = new int[n];
        int[] ptr = new int[n];

            int top = 0;

Construct cyclic binary sequence containing every length-n binary string exactly once as substring.

Hamiltonian Flights

bitmask DP · Hamiltonian paths
1. Goal / Pattern
Count directed routes from 1 to n that visit every city exactly once.
2. Best Approach
O(2ⁿ·n²) time, O(2ⁿ·n) space for n≤20; bitmask DP.
3. State / Invariant
dp[mask][u] = number of ways to visit exactly mask and end at u, without visiting n early.
4. Algorithm
Start mask {1}; append unvisited intermediate city. Finally transition from full non-n mask to n.
5. Traversal Order
Masks increase numerically; transitions always add one bit. Use edge multiplicities for parallel flights.
6. Catch / Hook
“Keep destination n for the final step.” This removes useless states and enforces Hamiltonian endpoint.
7. Similar / Difference
Elevator Rides also uses subsets, but tracks best packing. This counts ordered visits with a fixed endpoint.
8. Interview One-Liner
“The mask records visited cities and the endpoint tells which outgoing edge can extend the partial Hamiltonian route.”

import java.io.*;
import java.util.*;

public class Main {

    static final long MOD = 1_000_000_007L;

    public static void main(String[] args) throws Exception {
        FastScanner fs = new FastScanner();
        int n = fs.nextInt(), m = fs.nextInt();
        long[][] cnt = new long[n][n];
        for (int i = 0; i < m; i++) {
            int u = fs.nextInt() - 1, v = fs.nextInt() - 1;
            cnt[u][v]++;
        }
        if (n == 1) {
            System.out.println(1);
            return;
        }

        int V = n - 1;              // cities 0..n-2; destination n-1 is final only
        int states = 1 << V;
        int[] dp = new int[states * V];
        dp[V] = 1;                  // mask 1, ending at city 0

        for (int mask = 1; mask < states; mask++) {
            if ((mask & 1) == 0) continue;
            int base = mask * V;
            for (int u = 0; u < V; u++) {
                int ways = dp[base + u];
                if (ways == 0) continue;
                for (int v = 1; v < V; v++) if ((mask & (1 << v)) == 0 && cnt[u][v] != 0) {
                    int nm = mask | (1 << v);
                    int idx = nm * V + v;
                    long add = (ways * cnt[u][v]) % MOD;
                    long nv = dp[idx] + add;
                    if (nv >= MOD) nv -= MOD;
                    dp[idx] = (int) nv;
                }
            }
        }

        int full = states - 1;
        long ans = 0;
        for (int u = 0; u < V; u++) {
            ans = (ans + dp[full * V + u] * cnt[u][n - 1]) % MOD;
        }
        System.out.println(ans);
    }

Knight's Tour

backtracking · Warnsdorff heuristic
1. Goal / Pattern
Construct a knight tour that visits every chessboard square exactly once from given start.
2. Best Approach
Backtracking with Warnsdorff ordering; search is tiny in practice for 8×8 and recursion depth is only 64.
3. State / Invariant
board[r][c] is visit step; zero means available. DFS step k has exactly k−1 marked squares.
4. Algorithm
Try legal next moves ordered by fewest onward legal moves first (Warnsdorff).
5. Traversal Order
Heuristic order is critical for speed; it does not change correctness because failed branches backtrack.
6. Catch / Hook
“Go to the most constrained square first.” Input is x then y, so board index is [y−1][x−1].

Download Speed

max flow · Dinic
1. Goal / Pattern
Find maximum total capacity that can be sent from server 1 to server n.
2. Best Approach
Dinic: O(E·V²) worst-case, much faster in practice; O(n+m) residual graph space.
3. State / Invariant
Residual edge capacity tells how much more flow may pass; reverse capacity stores cancelable flow.
4. Algorithm
BFS builds level graph; DFS sends blocking flow only along increasing-level residual edges.
5. Traversal Order
Repeat BFS phases until sink unreachable; reset DFS pointers every phase.
6. Catch / Hook
“Residual reverse edges allow flow to be undone and rerouted.” Use long capacities.
7. Similar / Difference

School Dance

bipartite matching · Hopcroft–Karp
1. Goal / Pattern
Maximum number of compatible boy-girl pairs in a bipartite graph.
2. Best Approach
Hopcroft–Karp O(E√V) time, O(V+E) space.
3. State / Invariant
matchL[u] and matchR[v] are symmetric current matching partners; 0 means unmatched.
4. Algorithm
BFS builds layers from all free left nodes; DFS finds vertex-disjoint shortest augmenting paths.
5. Traversal Order
Each BFS phase fixes levels; DFS respects levels to augment many shortest paths in parallel.
6. Catch / Hook
“Augmenting path flips matched/unmatched edges and increases matching by one.”

            out.append('\n');
        }
        System.out.print(out);
    }

    static final class FastScanner {
        private final InputStream in = System.in;
        private final byte[] buffer = new byte[1 << 16];
        private int ptr = 0, len = 0;

        private int read() throws IOException {
            if (ptr >= len) {
                len = in.read(buffer);
                ptr = 0;
                if (len < 0) return -1;
            }
            return buffer[ptr++];
        }

        int nextInt() throws IOException {
            int c;
            do { c = read(); } while (c <= 32);
            int sign = 1;
            if (c == '-') { sign = -1; c = read(); }
            int val = 0;
            while (c > 32) {
                val = val * 10 + (c - '0');
                c = read();
            }
            return val * sign;
        }

        long nextLong() throws IOException {
            int c;
            do { c = read(); } while (c <= 32);
            int sign = 1;
            if (c == '-') { sign = -1; c = read(); }
            long val = 0;
            while (c > 32) {
                val = val * 10 + (c - '0');
                c = read();
            }
            return sign == 1 ? val : -val;
        }

        String next() throws IOException {
            int c;
            do { c = read(); } while (c <= 32);
            StringBuilder sb = new StringBuilder();
            while (c > 32) {
                sb.append((char) c);
                c = read();
            }
            return sb.toString();
        }
    }

Most Common Graph Bugs

Using DFS for unweighted shortest path: DFS finds a path, not necessarily shortest. Use BFS.
Using Dijkstra with negative edge: It is invalid; use Bellman–Ford or another correct method.
Marking visited too late: Mark when enqueuing/pushing so parent and distance are not overwritten.
Undirected cycle false positive: Skip only the parent edge; directed cycle logic is different.
Integer overflow: Distances, costs, flow and path counts commonly require long.
Not reversing reconstruction: Parent walks go target → source; reverse before printing.
Wrong SCC pass order: Finish order on original graph, then process reverse graph in reverse finishing order.
Euler path validation: Check degree balance and verify produced route has exactly m+1 vertices.
Residual misunderstanding: Reverse residual edge does not mean original graph edge; it represents cancelable flow.
